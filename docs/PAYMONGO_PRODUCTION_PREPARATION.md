# One KJM MAIN application — production payment path prepared, disabled

The existing booking UI and `/api/paymongo/{checkout,methods,webhook,reconcile}` endpoints now reuse the same payment engine with explicit environment separation. No copied website, synthetic booking, production SQL application, environment replacement, or payment creation occurred.

Default TEST mode still accepts only the dedicated TEST Supabase project, test bookings, `sk_test_` credentials, false `livemode` and test signatures. Explicit `PAYMONGO_MODE=live` selects only the original production project, non-test bookings, separate LIVE credentials, true `livemode`, live signatures and LIVE RPC/table names. A TEST secret or TEST receipt cannot satisfy the LIVE path. No automatic fallback across modes is allowed. Existing real database configuration remains unchanged; Pay Online currently stays unavailable/preview-only.

## Prepared production migration

`202610130026_paymongo_live_booking_payments.sql` requires the existing production booking/payment/deposit/terms migrations through 023. Do **not** apply TEST migrations 024/025 to production as dependencies. Migration 026 is not applied or database-runtime tested. It adds separate LIVE Checkout intents/receipts/events, forced RLS, admin-only ledger reads, service-only mutation/readiness RPCs, disabled readiness flags and a QR Ph method allowlist. One immutable intent per finalized confirmed booking freezes price, owner, unit and dates. External session creation has a single durable claim; ambiguous creation requires recovery of the existing session and never a replacement POST.

Verified settlement records the rental amount in the existing `payment_intents`, `payment_attempts` and `payment_events` tables atomically; existing ADMIN balances consume those records. The cash-only receipt trigger is extended only for a matching immutable LIVE provider receipt, not arbitrary non-cash/manual rows. Cash payments for bookings without an online intent remain unchanged. Existing handover/deposit/document guards remain authoritative; no reservation is auto-confirmed or revived. Cancellation/expired Checkout receipts go to review and do not automatically credit an expired booking. Security deposits remain handled separately at pickup under the approved booking snapshot (currently ₱2,500 refundable cash), never included in the hosted rental charge.

## Deliberate safety limits / remaining operations

No automatic refunds or cash fallback after an ambiguous Checkout is implemented. An intent permanently blocks a second charge; an expired/failed/uncertain session requires reconciliation and operator resolution before any alternative payment. Late/refunded/disputed/multiple provider payments require monitored review; do not launch without an operational resolution/refund procedure. Existing offline financial adjustment tools are not a PayMongo refund API. Provider compatibility, production database runtime and end-to-end activation remain unverified. Dedicated LIVE ledger statuses are available through admin RLS, but this MAIN-only work does not add a separate ADMIN exception-review screen.
