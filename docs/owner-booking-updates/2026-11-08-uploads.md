# Booking uploads and signature choices

The previous document path sent file bytes through a Vercel function while the form advertised an 8 MB file limit. A production probe reproduced HTTP 413 `FUNCTION_PAYLOAD_TOO_LARGE` for a 5,000,000-byte request; the same endpoint returned its normal ownership denial for a tiny request. The owner's exact failed file is unavailable, so this establishes a confirmed failure path rather than identifying that file.

New checkout code obtains a path-scoped, non-overwriting private Storage upload token. The browser sends the bytes directly to `identity-verification`. Completion sends only a signed metadata ticket. The ticket binds the browser access hash, booking, random path, kind, MIME, size and 30-minute completion deadline. Existing database registration checks still verify private-object metadata and booking/document eligibility. Duplicate completion is idempotent. The private bucket and existing ownership checks remain in place. Error messages now explain failed uploads or expired bookings.

Customers can select Draw signature or Upload image. Signature uploads accept PNG/JPG/WebP up to 8 MB, normalize locally to a small PNG, and are decoded, checked for blankness, bounded, stripped of metadata and normalized again on the server. No public signature URL is created. Migration 047 adds a private immutable PNG field and service-only atomic finalization function. Existing drawn and typed records remain readable; replacement of a recorded signature is denied. The Admin contract embeds the saved image with signer, time and terms version.

Validation includes an exact 8,388,608-byte private direct upload using the public client and a scoped upload token; real Storage metadata registration and uploaded-signature finalization in a rolled-back database transaction; same-signature retries; wrong-browser, changed-signature, invalid-image and immutable-record checks. No customer booking or payment was created by these checks. Synthetic Storage bytes are removed after verification. The signature interface was checked at a narrow content width, including local file selection and preview. A generated contract's signature page was rendered and reviewed.

Apply migration 047 before publishing either app. Both sites deploy through their existing Git integrations. Customers with a previously open checkout should refresh to load the updated upload code; expired requests require dates to be selected again.

## Mobile signing and Admin preview

Drawing now opens only after tapping Sign here / Edit signature. The normal checkout contains a read-only preview with vertical touch panning enabled. The native modal contains the active drawing area, locks background scrolling, validates before Done, restores the previous signature on Cancel/Escape, and returns focus to the trigger. Upload image remains available. Browser checks covered opening, drawing, Done, clearing then cancelling, retained strokes, and the phone viewport.

Admin booking details show the immutable saved signature below the rental details, including signer, Manila signing time, method and terms version. Both drawn and uploaded signatures are read-only; unsigned records are explicitly labelled. Existing contract export remains available. No migration or existing-record changes are required for this follow-up.
